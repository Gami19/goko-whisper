# バックエンド

未実装。ゴールの4桁コードは、いま `GoalPage` がブラウザ上でランダム生成している。発行・消込・達成者数だけをサーバーに置く。スタンプの記録は端末の `localStorage` で完結し、取得のたびに API は呼ばない。

---

## データの流れ

```
[参加者]
  │
  ├─ 標準カメラで QR（?stamp=spot1|spot2&token=...）
  │      ↓
  ├─ localStorage にスタンプを記録（通信なし）
  │
  └─ スタンプが両方揃い、ニックネーム入力済み
         ↓
    POST /api/token/issue
         ↓
    4桁コードを localStorage に保存して表示
         ↓
    スタッフが特典を渡し、確認を押す
         ↓
    POST /api/token/verify
         ↓
    使用済み。画面は引換済みになる
```

---

## API

ベース URL はフロントの `VITE_API_BASE_URL`。

### `POST /api/token/issue`

ゴール到達時に未使用の4桁コードを発行する。

- リクエスト: `{ "nickname": string }`
- レスポンス: `{ "code": string, "issuedAt": number }`
- 同じ参加者が再訪したときは、フロントが保存済みコードを再表示する。再発行しない。
- コードは `1000`〜`9999`。発行時に未使用のものだけを割り当てる。

### `POST /api/token/verify`

スタッフの確認でコードを使用済みにする。二重受け取りを防ぐ正はこちら。参加者の `localStorage` だけを消込済みにしても、ストレージ削除や別端末で同じコードを再提示できる。

- リクエスト: `{ "code": string, "pin": string }`
- 成功: 使用済みとして記録し、達成者数に含める
- 失敗: 不明なコード、使用済み、PIN 不一致を区別して返す

確認 UI は参加者のゴール画面に置く。スタッフ用の短い PIN を一緒に送る。受付が端末を持ち回らなくて済む。PIN は環境変数に置き、リポジトリには平文で置かない。

### 達成者数

スタッフが件数を見るための参照を用意する（管理用ルート）。件数は発行数ではなく、消込済みの件数。

---

## 永続化

コードの使用状態と件数はプロセスメモリに置かない。再起動や、Cloud Run 等のインスタンス入れ替えで消える。

短期イベントでは次のどちらかにする。

- 常時1インスタンスの SQLite
- Cloudflare D1 のように、複数インスタンスから同じデータベースを見る

ローカルの `data.json` は、単一プロセスのときだけ成立する。水平に増える実行環境では使わない。

有効期限の5分では、記念館の行列で受け取れなくなる。コードはイベント当日中有効にする。画面のカウントダウンを残すなら演出にとどめ、失効では受け取れなくしない。
